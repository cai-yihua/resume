End-to-End xApp Generation

High-level network intent in, a control application deployable on a Near-RT RIC out. Verification Before Going Live

Built the xApp lifecycle control platform governing both the real and the digital twin O-RAN RIC clusters, and integrated the digital twin simulation environment: a strategy is deployed to the twin and evaluated against KPM, and reaches the live network once it meets the goals set up front

Outcome: Scheduling decisions verified before they go live

Making LLM Output Dependable

Built output checking with an automated iteration loop: format and specification checks on the generated output feed back into the prompt producing the xApp strategy, so quality converges round over round

Outcome: Audited the triggers of 27 reruns; 52% traced to three checks later judged to be testing the wrong thing, and removed

Measure First, Then Change

Measured end-to-end runtime (15–35 minutes) and per-stage distribution across 137 archived runs, establishing where the bottleneck actually was before changing anything

Outcome: Measured an inference cache invalidation costing 16.8% extra per round and corrected the configuration; post-change runtime is being re-measured

Intent-Driven Network Management System

ITRI commissioned research — Chip-Driven 6G Communications Industry Technology Program · 6G resilient network management

Mar 2025 - Jan 2026

github.com/cai-yihua/ITRI-Intent-Based

The system follows the 3GPP intent model (Intent → IntentExpectation → ExpectationTarget, scoped by Context), turning "what should be achieved" into quantifiable targets that an execution engine issues to the SMO, with closed-loop monitoring to confirm the targets are met; intent translation is driven by an LLM.

Joined mid-project on a codebase established by 3 senior members, later independently responsible for release management, deployment and system integration, documentation deliverables, system maintenance and external technical coordination.

Automated Deployment

Collapsed installation of the frontend, backend, Dify, n8n and PostgreSQL into a single deployment script: infrastructure containers, then core service containers, then the backend and frontend, with service registration and workflow setup performed automatically; all configuration externalized to .env so the same process reproduces across dev, test and production

Impact: Deployment time reduced from 1hr+ to 4 minutes

Deployment & Operations Standards

Authored the non-functional specification chapter of the software specification: deployment broken into environment preparation, source acquisition and version pinning, system configuration, automated execution and post-deployment verification; operations covering routine monitoring, change management, incident handling with root cause analysis, patching with rollback plans, and backup and recovery drills

Impact: A standard process future maintainers can follow directly

Post-Deployment Verification

Defined three levels of acceptance: service reachability (UI and API endpoints), module integration (whether each subsystem's workflows and resources were provisioned correctly by the script), and an end-to-end test running one complete intent through frontend → backend → translation engine → execution engine

Impact: Deployment success judged by criteria, not by eyeballing it

Automated Testing

Decomposed test items into Gherkin scenarios — given this state, when this happens, expect this — with Airtest simulating frontend user operations to verify UI rendering and E2E flows, in a highly decoupled test architecture

Impact: Completed 29 critical test cases

Requirements & Intent Translation Design

Served as technical liaison clarifying ITRI requirements, adding features within the modular architecture while keeping it decoupled. Intent translation is LLM-driven: designed the prompt workflow (chain-of-thought to reduce hallucination, tool invocation specifications, context condensation) and tuned parsing accuracy through iterative testing

Impact: Win-win on features and cost; markedly more stable output

Agent Prompt Design Methodology

Distilled a repeatable agent design process out of this project: define the problem → decompose features → plan tools and steps → set specification metrics → test intent parsing and tool invocation → backtrack to adjust the prompt and feature partitioning when results deviate

Impact: Structured input in place of trial and error; carried forward into this year's program

Release & Change Records

Split Backend / Dashboard into git submodules with a version-to-milestone table recording the versions of the main repository and its submodules alongside every change, and audited all third-party licenses

Impact: Every version's scope and changes stay traceable

Time-Series Anomaly Detection

Trained an LSTM model over ~740MB of simulated time-series data to detect anomalies in network state data

Impact: 100% anomaly detection rate in the simulated environment
