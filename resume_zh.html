AI-RAN / O-RAN · AI Agent System Design

蔡宜樺

國立臺灣科技大學電子工程研究所碩士生，專注於 AI-RAN / O-RAN 智慧網路與 AI Agent 系統設計。目前的研究題目是讓 AI Agent 讀懂高階網路意圖，自動產出可部署到 Near-RT RIC 的控制策略，並在數位雙生環境驗證後才下發實網。具備工研院委託計畫、國科會計畫的核心開發經驗與兩次業界暑期實習。

個人特質與專業風格

喜歡處理富有邏輯性或系統性的任務，願意接受挑戰、不斷嘗試新事物。性格小心謹慎，面對任務展現高專注度與細緻度，嚴格確保交付產出的精準度與架構品質。專業核心聚焦於系統架構規劃與技術文件規範管理，曾參與 6G AI/ML 平台技術文件標準制定、AI Agent 與後端軟體架構設計。具備微積分助教與專題生指導經驗，兼具嚴謹的邏輯思維與清晰耐心的跨團隊溝通協作能力。

01

核心能力

01

O-RAN 智慧網路開發

在 Near-RT RIC 上開發 xApp：透過 E2 介面讀取 KPM 指標、下達控制決策。能從零部署 O-RAN 測試環境（CU / DU / RU 與 RIC），並定位元件啟動與連線問題。

02

AI Agent 系統設計

設計多階段 Agent 工作流與工具調用契約，讓大型語言模型穩定產出可編譯、可部署的程式碼；並以產出檢查的結果回推 prompt 與功能劃分的修正。

03

系統交付與驗證

從架構圖、API 規格到容器化部署與自動化測試，能把系統連同文件一起交到別人手上。具備 Docker / K8s 部署經驗，並能以 Gherkin 把測試寫成「在什麼情況下、做了什麼、應該得到什麼」的行為情境，進行自動化 UI 與 E2E 驗證。

端到端 xApp 自動生成

輸入高階網路意圖，輸出可部署於 Near-RT RIC 的控制應用程式。工作流涵蓋問題診斷、策略設計與程式碼生成三段，每段之間以結構化契約交接；任一段判斷不明確即中止，確保下游接手的是已確認的分類

成果：2026/07 如期完成第一階段交付

策略上線前的雙生驗證

自行開發 xApp 生命週期控制平台，同時管理實體與數位雙生兩套 O-RAN RIC 叢集；並串接數位雙生模擬環境，策略先在雙生部署、取 KPM 指標推演，達到當初設定的目標才下發實網

成果：網路調度決策可先驗證再上線

讓 LLM 的產出穩定可用

建立產出檢查與自動迭代機制：執行時檢查產出的格式與規格符合度，並以檢查結果回頭調整生成策略的 prompt，讓 xApp 產出品質逐輪收斂

成果：盤點 27 次重跑的觸發來源，其中 52% 來自三條後來判定「驗錯東西」的檢查，已移除

用量測決定要改什麼

以封存的 137 筆執行紀錄量測端到端耗時（15–35 分鐘）與各段分佈，先確認瓶頸落在哪一段，再據此決定要改什麼

成果：量到一個推論快取失效每輪多付 16.8% 成本並修正設定；改造後的端到端時間正在重新量測

意圖驅動組網管理系統

工業技術研究院 (ITRI) 委託研究 — 晶片驅動 6G 通訊產業技術開發計畫．6G 全域韌性網管技術

2025/03 - 2026/01

github.com/cai-yihua/ITRI-Intent-Based

系統依 3GPP 意圖模型（Intent → IntentExpectation → ExpectationTarget，搭配 Context 限定生效範圍），把「要達成什麼」的高階需求轉成可量化目標，再由意圖執行引擎下發 SMO，並以閉環監控驗證是否達標；意圖轉譯以 LLM 為核心技術。

中途加入由 3 位學長建立的專案，後期獨立負責專案版本管理、部署與系統整合、文件交付、系統維護與對外技術對接。主動提出架構優化方案，職責轉換期先規劃再討論確認方向。

自動化部署優化

把前端、後端、Dify、n8n、PostgreSQL 等模組的安裝收斂成單一部署腳本：依序啟動基礎設施容器、核心服務容器與前後端，並自動完成服務註冊與工作流設定；組態全部外部化到 .env，讓同一套流程能重現於開發、測試與生產環境

成效：部署時間從 1 小時+ 縮短至 4 分鐘

部署與維運流程規範

撰寫軟體功能規格書的非功能規格章節，把部署拆成環境整備、原始碼取得與版本定位、系統組態、自動化執行、部署後驗證五個階段；維運面定義日常監控、組態變更管理、事件與問題管理（含根因分析）、更新修補與回滾計畫、備份還原與演練

成效：交付後續維護者可直接依循的標準流程

部署後驗證

定義三層驗收：服務可及性（UI 與 API 端點）、模組串接（各子系統的工作流與資源是否由腳本正確部署）、端到端功能測試（跑一筆完整意圖，驗證前端 → 後端 → 意圖轉換引擎 → 意圖執行引擎的資料流）

成效：部署完成與否有明確判準，不靠人工目視

自動化測試

以 Gherkin 語法拆解測試項目（在什麼情況下、做了什麼、應該得到什麼），搭配 Airtest 模擬前端使用者操作，驗證 UI 渲染與 E2E 流程，設計高解耦測試架構

成效：完成 29 個關鍵測試案例

需求工程與意圖轉譯設計

擔任技術窗口釐清工研院需求，在模組化架構中新增功能並維持解耦。意圖轉譯以 LLM 為核心，設計 Agent Prompt 工作流（思維鏈降低幻覺、工具呼叫規範、上下文濃縮），透過迭代測試優化意圖解析準確度

成效：功能與成本雙贏，輸出穩定性顯著提升

Agent Prompt 設計方法論

從這個專案整理出一套可重複的 Agent 設計流程：定義問題 → 拆解功能 → 規劃工具與步驟 → 制定規範指標 → 測試意圖解析與工具呼叫 → 不符預期則回溯調整 Prompt 與功能劃分

成效：以結構化輸入取代反覆試誤，後續沿用到今年度計畫

版本與變更紀錄管理

以 git submodule 拆分 Backend / Dashboard 多倉庫結構，建立版本－里程碑對應表，逐版記錄主倉庫與子模組的版本及變更項目，並盤點全部第三方套件授權

成效：每一版的功能範圍與變更項目皆可追溯

時序網路異常偵測

以 LSTM 模型處理約 740MB 模擬時序資料，對網路狀態數據進行訓練與異常偵測

成效：模擬環境下達到 100% 異常偵測率
